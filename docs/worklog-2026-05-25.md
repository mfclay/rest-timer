## What was built

### Lakebed capsule structure

```
lakebed-version/rest-timer/
  server/index.ts     — schema, queries, mutations
  client/index.tsx    — full Preact app (~960 lines), all components inline
  shared/types.ts     — TimerMode, SetRecord, Session, UserSettings, LiveSet
  shared/utils.ts     — fmtTime, fmtTimeLong, parseTimeStr, DEFAULT_SETTINGS
```

### Server (`server/index.ts`)

Two tables:
- `sessions` — one row per workout session; sets embedded as JSON blob (`setsJson`)
- `userSettings` — one row per user; all settings as JSON blob (`data`)

Lakebed v0 only supports `string()` and `boolean()` column types — no `number()`. All numeric fields (timestamps, durations) stored as strings and converted on read with `Number()`.

Mutations:
- `saveSession` — inserts a session on "End session"
- `saveUserSettings` — upsert pattern (query first, then update or insert)

### Client (`client/index.tsx`)

Preact app using `useQuery` / `useMutation` / `useAuth` from `lakebed/client`. Key features:

- Three-mode state machine: `ready` → `lifting` → `resting` → `ready`
- Timer via `setInterval` at 100ms; refs used to avoid stale closures
- Exercise / weight / reps config zones with paged chunk grids
- History modal reading from `useQuery("sessions")`
- Settings modal with per-exercise targets, quick weights, quick reps, sound, wake lock, unit
- Export to CSV and JSON (client-side blob download)
- Google sign-in via `<SignInWithGoogle />` from `lakebed/client`; guest access allowed
- Wake Lock API and Web Audio API chimes (no external deps)

---

## Key decisions and constraints

| Constraint | Solution |
|---|---|
| No `number()` column type | Store timestamps and durations as strings; convert with `Number()` in queries |
| Sets would require nullable number columns | Embed as JSON blob in `setsJson: string()` on the session row |
| Settings schema evolves often | Embed all settings as JSON blob in `data: string()` on `userSettings` row |
| No CSS/font pipeline in Lakebed | Tailwind classes directly in JSX; system sans-serif font |
| No npm packages in app code | Web Audio API for chimes, native Fetch/WakeLock APIs |

## UI iterations

### Responsive layout (~1000px viewport)
Header was overflowing at medium widths. Fixed with Tailwind responsive classes:
- Auth strip text hidden below `xl` (`hidden xl:block`)
- History/Notes button labels hidden below `xl` (`hidden xl:inline`)
- Responsive padding on root, header, and buttons (`px-4 sm:px-6 lg:px-10`, etc.)
- Bottom panel height reduced from `min(420px, 55vh)` to `min(340px, 46vh)`

### Timer color states
Matches the original `index.html` logic exactly:
- **Lifting / ready**: white
- **Resting (under target)**: green `#5DCAA5`
- **Resting (at target, within 15s)**: green with green glow border
- **Resting (over target + 15s, "OVER REST")**: amber `#F2B84B` with amber glow border
- **Paused**: dimmed white

Timer, label, border glow, and primary button all change color together — they always match.

### ChunkGrid (exercise/weight/reps buttons)
- Fixed container height (`h-[218px]`) so buttons don't stretch when exercise names wrap
- Buttons use `h-full` so they fill the fixed container uniformly across all three zones
